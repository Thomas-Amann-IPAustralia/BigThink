IPAVentures horizon scan · methodological walkthrough

From Query to Shortlist

How the baseline scan of 30 August 2026 turned twenty search queries into 7,219 documents, fifteen topics and one ranked shortlist — traced stage by stage, including the two signals that turned out not to be signals at all.

This report answers one question: where did each of these signals come from? Not "what does the pipeline do in general" — that is docs/method.md — but how these specific fifteen topics were produced from these specific documents, and which of them deserve to be believed.

How to read this

Every technical passage is followed by a plain-language box like this one. If you skip the technical parts entirely and read only these, you will still get an accurate picture of what happened and what it is worth.

The short version: a computer read about seven thousand research papers, news articles and government datasets, grouped them by what they were about, worked out which groups were growing unusually fast, and then checked each group against what IP Australia has actually said it plans to do. It produced a ranked list. Two entries near the top of that list are mistakes, and this report shows exactly how they got there — because that is the most useful thing it can show you.

CONTEXT

Why this run is a baseline and not a comparison

Three things were true for the first time on 30 August 2026.

  • OpenAlex contributed data. OpenAlex meters its free tier in dollars per day per IP address, and a shared cloud runner has almost always spent that budget already. Every previous run retired the source at the first query and collected nothing from it. With an API key configured, all twenty queries succeeded.
  • The corpus was persisted. The scheduled workflow had never completed before, so no corpus had ever been published. This run wrote the first one — as a GitHub release, and mirrored to Cloudflare R2 at r2://bigthink-corpus/bigthink.duckdb.
  • The database started empty. Because there was no corpus to restore, this run collected from zero rather than adding to previous work.
Why the previous shortlist cannot be used as a comparison

Almost every headline number in this pipeline is percentile-ranked within its own run before it is used. The emergence score, the opportunity index and the composite rank all measure a topic's position against the other topics collected at the same time. Change the corpus and you change the population; change the population and every score moves, whether or not the world did.

In plain terms

The scores are marks on a curve, not marks out of ten. A topic scoring 0.84 did not clear some fixed bar — it came top of this class. A run full of dull topics still produces one scoring near the top.

So the sensible way to read the previous run against this one is as two separate photographs, not as before-and-after of the same thing.

STEP 0

Encoding what IP Australia says it will do

Before anything is searched for, the agency's own strategy is turned into a set of reference points that topics can later be measured against. Thirty-four of them, from four hand-curated YAML files.

The reference set every strategic-fit and asset-leverage score is measured against
Reference typeCountSource
Objective9Strategic Corporate Plan 2026-27
Initiative6Corporate Plan strategic initiatives (SI-1 … SI-6)
Critical technology7DISR List of Critical Technologies
Asset12What IP Australia would bring to a venture

Each reference carries two things: a paragraph of text, which becomes a vector, and a hand-written list of terms, which is matched literally. Both are needed. An embedding catches a topic that means the same thing in different words; the term list catches a topic that names the thing exactly — “geographical indications” must score against initiative SI-1 on the strength of the phrase, and embedding a whole paragraph can dilute that to nothing.

In plain terms

This is the yardstick. Everything the scan later calls “on strategy” means “close to one of these thirty-four things”.

That has a consequence worth holding onto: a trend the strategy does not describe cannot score highly on fit, however important it is. That is a property of the ruler, not a finding about the world.

That has not happened before on this project; GDELT in particular rate-limits by IP and drops connections mid-response, and previous runs logged a majority of its requests as failures.

The OpenAlex result needs reading carefully

OpenAlex is live, and that is a real change: twenty successful queries where previously there were none. But it contributed only 581 documents, 8% of the corpus — far less than its configuration allows.

Where the 581 comes from

The collector is configured for up to 5 pages of 200 records per query — a ceiling of 20,000 records. It returned 592, an average of 29.6 per query. Since a single page holds 200, no query reached even the end of its first page.

The cut is not the daily budget: a budget failure raises a permanent error and retires the source, and all twenty queries logged success. It is the relevance floor. min_relative_score: 0.4 makes the collector stop at the first result scoring below 40% of that query's own top relevance score, and OpenAlex's relevance scores decay steeply.

In plain terms

The key works. The tap is open. But there is a filter on it set tight enough that only the first few dozen results per question get through, and it closes as soon as one result looks much less relevant than the best one.

This is worth adjusting before the next run, and it is a one-line change. It is also not a bug — the filter exists because a keyword search returns a long tail of loosely-related material. The question is where to set it, and 0.4 is stricter against OpenAlex's scoring than it is against Crossref's.

STEP 2

Turning seven thousand documents into fifteen topics

Every document's title and abstract is converted into a 2,048-number vector, and documents whose vectors point in similar directions are grouped together.

The mechanics

Embedding. The hashing backend — character n-gram hashing with TF-IDF weighting. It needs no model download, which is what lets the pipeline run anywhere, but it matches vocabulary rather than meaning. Two papers saying the same thing in different words will not be recognised as related.

Clustering. Three passes: a leader pass assigning each document to the nearest cluster centre above cosine 0.30; a reassignment pass that removes the order-dependence of the first; and a merge pass for near-duplicate clusters. A document matching nothing is dropped, not forced into the nearest cluster, which would corrupt that cluster's centre.

Filtering. A cluster must hold at least 8 documents and at least 3 distinct terms. The second test exists because a run of dataset titles once produced a “topic” whose entire vocabulary was the word index.

News is held out. GDELT's 70-character multilingual headlines would dominate clustering, so they take no part in forming topics and are attached afterwards, at a looser threshold, once the centres are fixed.

In plain terms

Imagine every document as a point in a very large space, positioned by the words it uses. Clustering draws rings around points that sit close together, and each ring becomes a topic. Points that fall inside no ring are set aside.

The important limitation: this version measures shared words, not shared ideas. A paper on "automated decision-making" and one on "algorithmic administration" would land far apart despite meaning nearly the same thing.

Only 38% of the corpus made it into a topic

2,760 of 7,219 documents were assigned to one of the fifteen topics. The other 4,459 did not cluster tightly enough under a vocabulary-matching backend and appear in no score anywhere in this report.

And the assignment that did happen is very unevenly distributed. One topic — T0000, labelled image / patent / learning / watermark — holds 1,497 documents, which is 54% of everything assigned.

How the method handles its own catch-all

T0000 scores novelty 0.045 and coherence 0.337 — the lowest of both in the run. Novelty is measured as distance from the centre of the early corpus, so a score near zero means the topic is the corpus average: it has no distinct position. Its defining terms confirm it: image, patent, learning, watermark, watermarking, system, ai, dataset, training, quantum — watermarking and quantum computing are not one subject.

It ranked 15th of 15. The scoring demoted it without anyone intervening.

In plain terms

There is always a bin labelled "miscellaneous", and here it is enormous — over half of everything that got sorted. The good news is that the method noticed: a group that is about everything is about nothing, and it landed last.

The bad news is that a very large catch-all means the clustering threshold is no longer well-tuned for this corpus. It was calibrated against a different, smaller collection. This is the clearest thing to re-tune before the next run.

STEP 3

Deciding which topics are emerging

A topic being large is not interesting. A topic moving is. Four separate measurements establish movement, and then five attributes are combined into one emergence score.

The time series, and what is excluded from it

Each topic gets a count of documents per year, zero-filled across the whole 2018–2026 window — a topic absent until 2024 must show zeros for 2018–2023, or its growth is measured from a starting point that does not exist.

Why news is excluded from the timeline

GDELT is collected over a rolling 24-month window, so every one of its 2,040 documents carries a 2026 date. Counted in the yearly totals it would put more than a third of the corpus into a single slice, making every earlier year look sparse and turning flat topics into ones apparently "bursting" for eight consecutive years.

A source whose coverage does not span the analysis window cannot define a trend within it. News still counts toward attention and document totals — which is what it is actually evidence of.

Burst detection

Kleinberg's two-state automaton asks, for each year, whether the topic's share of that year's documents is better explained by its normal rate or by an elevated one, with a cost for switching between them. The lowest-cost sequence of states is found exactly, by Viterbi.

In plain terms

The crucial property is that a topic growing at the same rate as everything around it does not count as bursting. Without that, every subject in a growing collection would look like it was taking off.

So a burst means: this grew faster than its surroundings, in this particular year, by enough that the maths prefers to call it a different state.

Growth curve and Three Horizons

A logistic S-curve is fitted to the cumulative counts by direct least squares over a grid of candidate shapes. The fitted position along that curve at the final year is the topic's maturity, and maturity — not age — decides its Three Horizons band.

A trap the code deliberately avoids

The textbook way to fit a logistic curve is to linearise it. It fails here. For a series still in its exponential phase, the linearised expression is near-straight for any sufficiently large ceiling, so maximising straightness picks the smallest ceiling and reports a young, fast-growing technology as saturated.

That inverts the horizon band for precisely the technologies a horizon scan exists to find. Fitting the curve itself has no such degeneracy, and a regression test guards it.

The five attributes

Rotolo, Hicks & Martin (2015) define emergence through five attributes. Each becomes one computable indicator, and the five are combined with fixed weights.

The emergence score. Weights are a considered judgement from the literature — not fitted to any known outcome.
AttributeHow it is measuredWeight
NoveltyCosine distance from the early-corpus centre — how far this sits from where the field already was0.25
GrowthAnnual growth rate blended with Kleinberg burst intensity0.30
CoherenceHow tightly the documents cluster around their own centre0.15
ImpactCitation percentile, computed within each source0.20
UncertaintySpread of institutions and evidence types working on it0.10
Two details that change results materially

Impact is ranked within source. arXiv reports no citation counts at all. Ranked globally, every preprint would sit at the bottom and the fastest-moving evidence in the corpus would be systematically penalised. Where a source reports no citation variation whatsoever, its documents get a neutral 0.5 rather than a confident wrong answer.

Attributes are percentile-ranked before weighting. The five have very different natural ranges — novelty spans roughly 0.05–0.88 here while growth spans 0.00–0.34. A plain weighted sum of raw values is dominated by whichever attribute happens to be widest, so the configured weights would describe something other than what the code does.

emergence = 0.25·rank(novelty) + 0.30·rank(growth) + 0.15·rank(coherence) + 0.20·rank(impact) + 0.10·rank(uncertainty)
In plain terms

Five different questions get asked about each topic — is it new? is it growing? is it one clear subject? are people citing it? are lots of different organisations involved? — and each topic is placed in order against the others on each question separately, before the five orderings are blended.

Ranking each question separately is what makes the stated weights honest. Otherwise whichever question happened to produce the widest spread of raw numbers would quietly dominate everything.

STEP 4

Deciding which emerging topics matter to IP Australia

Two scores, against the Step 0 reference set. Each blends an embedding similarity with a literal term-overlap term, and each takes the score of the topic's single best-matching reference rather than an average across all of them — a trend speaking directly to one objective is a strong fit, and averaging it against eight unrelated objectives would bury it.

The two axes
strategic fit = 0.7·cosine + 0.3·lexical (against objectives and initiatives) asset leverage = 0.6·cosine + 0.4·lexical (against the asset inventory)

Each is multiplied by the reference's own priority weight — objectives 4.1 and 4.2 and initiative SI-3 carry 1.3, objective 3.2 carries 0.6 — so the strategy's own emphasis flows through. A DISR critical-technology match adds a fixed bonus, and is binary because the DISR list is a policy designation: a topic either falls in a national-interest field or it does not.

In plain terms

Strategic fit asks: has the agency already said it cares about this? Asset leverage asks: could the agency actually do something about it that others could not?

The second is the one that separates an interesting trend from a viable venture. A trend everybody can see and nobody has an advantage in is not an opportunity for anyone in particular.

In plain terms — and this one matters

The asset-leverage axis spans a very narrow band, which means it is barely distinguishing between topics. But because scores are converted to rankings before being combined, it still contributes its full configured 25% of the final order.

So a quarter of the ranking is being driven by an axis whose underlying differences are tiny. Small gaps on this axis should not be treated as meaningful. The cause is the vocabulary-matching embedding backend: a topic's terms and a 60-word asset description share almost no exact words, so only the literal term list carries any signal.

STEP 5

The opportunity index, and why it is kept out of the ranking

A composite of four measures, percentile-ranked within the run and combined. It is not a market size, not a dollar figure, and cannot be converted into one. It answers only: of two topics in this run, which shows more of the signals that usually accompany a large opportunity?

Weight redistribution, visible

The index is configured with five components. patent_activity had no data — PatentsView requires an API key that is not set — so its 15% was redistributed proportionally across the other four rather than being scored as zero:

configured → effective (patent_activity omitted) research_growth 0.30 → 0.3529 attention 0.25 → 0.2941 policy_salience 0.20 → 0.2353 attention_tone 0.10 → 0.1176 patent_activity 0.15 → —

Without redistribution, disabling a source would silently shrink every topic's index by 15% and the ranking would look unchanged while measuring something different.

Two topics — T0014 and T0013, at 10 and 14 documents — fall below the 15-document floor and carry no index at all. They are suppressed rather than scored zero: an unmeasurable quantity and a low one are different claims.

In plain terms

There is no patent data in this run at all. For an IP office's horizon scan that is a real gap — patents are the lagging confirmation half of the picture — and it is worth stating in any briefing rather than quoting the configured weights as though all five components were present.

The index is deliberately left out of the headline ranking. It is the least well-founded number in the pipeline, and folding it into the order everyone reads first would launder that weakness.

TRACE

Three signals, followed end to end

The stages above describe the machinery. What follows is the machinery applied — the full provenance of three specific entries on that list, chosen because they show three different outcomes.

Signal 1 — AI and patent examination holds up

Ranked first. The strongest candidate in the run, and the one that survives inspection.

seed queries→129 documents→cluster @ 0.30→burst 2025→H2 · strong→SI-3→rank 1

How it was identified, step by step. 129 documents clustered around the terms artificial intelligence, patent, examination, inventorship, patent law. The Kleinberg automaton flagged 2025 — 35 documents against a prior run of 4 to 19 — as a genuine elevated state rather than corpus-wide growth. The logistic fit put maturity at 0.434, which falls between the 0.35 and 0.75 cut-points and so places it in H2, the contested middle. Annual growth ran at +19.8%.

On the five attributes it scored novelty 0.72, growth 0.28, coherence 0.43, impact 0.75 and uncertainty 0.66 — a composite emergence of 0.582. Its best strategic match was initiative SI-3, AI and Automated Decision Making in IP administration, at 0.191, the second-highest fit in the run and against one of the two highest-weighted references in the strategy. Asset leverage reached 0.098, second only to 0.101 on that compressed axis.

On the opportunity index its research-growth component scored 0.929 — the second-fastest-growing topic in the run. It sits in the “act” quadrant: above the median on both strategic fit and asset leverage.

The evidence check

The documents nearest the centre are Artificial Intelligence and Patent Law, Artificial Intelligence and Inventorship, Impact of Artificial Intelligence on Patent Law, Artificial intelligence is breaking patent law (Nature, 2022) and Patent Analysis of Artificial Intelligence: A Comprehensive Study 2013–2022.

That is a coherent theme, from named venues, spanning eight years, and it means what the label says it means.

In plain terms

This one is real. A genuine body of research on what AI does to patent law and patent examination, growing steadily since 2018 and jumping sharply in 2025, that maps directly onto an initiative IP Australia has already committed to and weighted highly.

It is also, honestly, the least surprising thing the scan could have found — an IP office scanning for AI-and-IP topics found one. That is a point in favour of the machinery working, not evidence of a discovery.

Signal 2 — Wire arc additive manufacturing artefact

Ranked second, with the highest emergence score in the entire run. It is not a signal. It is one paper's peer-review history.

seed queries→27 documents→cluster @ 0.30→burst 2025→emergence 0.843→rank 2→discarded on reading

Every stage behaved correctly. The topic scored novelty 0.878 — nothing resembling it existed in the early corpus. Coherence 0.779, the highest in the run: these documents are extremely similar to one another. Growth 0.340, also the highest, with a burst correctly detected in 2025 and an annual growth rate of +32.5%. Weighted together, an emergence score of 0.843 — the top of the run by a wide margin.

Then you read the documents.

The eight documents nearest the centre

All eight are peer-review reports for a single paper — Artificial Intelligence in Wire Arc Additive Manufacturing: A Systematic Review and Patent Landscape Analysis — registered under DOIs 10.1002/eng2.70518/v1/review1, /v1/review2, /v1/review3, /v2/review1, /v2/review2, /v3/review1, /v4/review2 and /v4/review3.

Crossref registers peer-review reports as first-class records with their own DOIs. Four manuscript versions reviewed by up to three reviewers each produced a run of near-identical 2025 records, every one carrying the reviewed paper's title. Nineteen of the topic's twenty-seven documents fall in 2025, and all eight nearest its centre are reviews of this one paper.

Deduplication could not catch this: each review genuinely has a distinct, stable identifier. It is not a duplicate-detection failure. It is a record-type problem.

In plain terms

One engineering paper was reviewed by three reviewers across four drafts. The academic plumbing gave every one of those twelve-odd review comments its own permanent web address, carrying the paper's title. The scan collected them as if they were twelve separate research papers appearing out of nowhere in 2025.

Of course they clustered tightly — they have identical titles. Of course they looked novel — nothing like them existed before. Of course they burst — they all arrived at once. Every measurement was correct, and the conclusion was nonsense.

This is precisely why reading the source documents is not an optional final polish. It is the only check that catches this class of error, and no amount of re-weighting would have.

It is not the only one. Rank 6, delivery / service / government / local — which carries the highest opportunity index in the run at 0.689 — has the same problem. Its eight nearest documents are peer-review reports of a single paper: Financial Autonomy: Panacea for Improved Service Delivery in Imo State Local Government System. The topic's label reads like Australian public-service delivery. Its centre is reviews of a paper about local government finance in Nigeria.

Record types among the 120 documents nearest the fifteen topic centres

A related case appears at rank 8, where three of the nearest documents are titled simply References — book bibliographies registered with their own DOIs.

The fix

The Crossref collector already requests the type field, but uses it only as a fallback label when a record has no container title. It never filters on it. Excluding peer-review — and probably component, and back-matter titled References — would remove both artefacts at the source.

This is a small change, but it changes what every future run collects, so it belongs in the calibration log with a stated reason rather than being applied quietly.

Signal 3 — The catch-all correctly demoted

Ranked last, holding more than half of every document the scan managed to sort.

T0000 gathered 1,497 documents under the terms image, patent, learning, watermark, watermarking, system, ai, dataset, training, quantum. Watermarking and quantum computing are not one subject, and the scoring said so: novelty 0.045 and coherence 0.337, the lowest of each in the run, producing an emergence score of 0.321 and last place.

In plain terms

Novelty here is measured as "how far is this from the average of everything?" A score of 0.045 means this group is the average of everything — it has no particular position, because it contains a bit of everything.

That the method demoted it without being told to is genuinely reassuring. That it exists at all, and is this large, says the grouping threshold needs re-tuning for a corpus this size.

CHECK

What the arithmetic proves — and what it does not

The run generates a notebook that reads the finished corpus back out and recomputes four stored numbers from their stored inputs, verifying against the config snapshot recorded at run time rather than the file on disk today.

PASSEmergence score reproduced for all 15 topics — largest deviation 0, tolerance 1e-9
PASSThree Horizons band reproduced — 15 of 15 identical
PASSOpportunity index reproduced for 13 scored topics — largest deviation 9.71e-05, tolerance 1e-3 (the stored components are rounded to 4dp; that rounding is the whole error budget)
PASSComposite rank and ordering reproduced — deviation 0, and 15 of 15 positions identical

The last check calls the pipeline's own ranking function rather than reimplementing it, so the check cannot drift away from the code it is checking. The config on disk was confirmed identical to the config that produced the run.

In plain terms — the important distinction

All of this establishes that given this corpus and these weights, the shortlist follows. The sums are right. Nobody has to take the arithmetic on trust.

It establishes nothing whatsoever about whether the weights are right. Every weight here was set by reading the research literature and thinking, not by testing against a known outcome. Signal 2 makes the point vividly: the arithmetic was flawless and the answer was still wrong, because the input was wrong.

The useful argument to have about this document is about the scan frame, the weights and the topics — not about the sums.

NEXT

What to change before the next run

In priority order, from what this run actually showed.

  1. Filter Crossref record types. Two of fifteen shortlisted topics are single-paper peer-review clusters, one of them ranked second and one carrying the highest opportunity index in the run. This is the highest-value fix available and it is a few lines in one collector.
  2. Loosen the OpenAlex relevance floor. The best research source available is contributing 8% of the corpus because every query stops inside its first page. It is live and working; it is simply being filtered hard.
  3. Re-sweep the clustering threshold. The 0.30 value was calibrated against a different, smaller corpus. On this one the catch-all topic holds 54% of everything assigned, and 62% of the corpus is in no topic at all.
  4. Switch the embedding backend. Asset leverage spans 0.030–0.101 and still drives a quarter of the ranking. The vocabulary-matching backend is the root cause, and this remains the single highest-value change to the method as a whole.
  5. Validate against a known past opportunity. Still the largest gap. Until the ranking is tested against something IP Australia already pursued, it remains a hypothesis about ranking.
And one thing not to change

The evidence cards. Reading the primary documents behind a topic is the cheapest and most reliable quality control in this entire method, and it is the only step that caught the two artefacts. Every other check in the pipeline passed them.
