# A Computational Opportunity-Identification Pipeline for IPAVentures

## TL;DR
- **Build a five-stage code pipeline — signal collection → trend/emergence detection → strategic-fit scoring → value-pool estimation → opportunity synthesis — that operationalises anticipatory-innovation foresight (Three Horizons + STEEPV/PESTLE horizon scanning + Rotolo's five emergence attributes) computationally rather than as a workshop.** Almost every stage maps onto free, API-accessible data and extends your existing BERTopic/YAKE/sentence-transformer stack.
- **The single most powerful extension is to add BERTrend-style temporal signal classification (strong/weak/noise) plus Kleinberg burst detection on top of your BERTopic pipeline, feeding a Rotolo-derived emergence score, then scored against IP Australia strategy via a 2×2 strategic-fit × asset-leverage matrix.** This is the computational core other IP offices (WIPO Technology Trends, EPO Deep Tech Finder) have already proven with patents + NLP.
- **Your best free data sources are OpenAlex (research), Lens.org / PatentsView / Google Patents BigQuery (patents), IP Australia's own IP RAPID/IPGOD (assets + IP trends), data.gov.au + the DISR Critical Technologies list (strategy/policy), and GDELT + Google Trends (market/attention signals).** Value-pool sizing remains the hardest to automate and should stay a lightweight, assumption-driven relative index with human review — not a dollar figure.

## Key Findings

1. **The four-input framing (strategy + assets + trends + value pools → ranked opportunities) has no single named "off-the-shelf" method, but it maps cleanly onto a stack of established frameworks** that can each be operationalised computationally: Three Horizons for time-phasing, STEEPV/PESTLE for the scan taxonomy, Rotolo et al.'s five emergence attributes for measuring "emergence," patinformatics white-space analysis for asset/opportunity gaps, and a 2×2 prioritisation matrix for ranking.

2. **The public-sector foresight toolkits (OECD OPSI, UK GO-Science Futures Toolkit, APS Innovation Toolkit) are overwhelmingly workshop/qualitative.** They give you the vocabulary and process scaffolding (horizon scanning, driver mapping, Three Horizons, scenarios, Delphi) but almost none of the computation. Your contribution is to build the data-science layer underneath them.

3. **The data-science literature for computational horizon scanning is mature and directly reusable**: Kleinberg burst detection, BERTrend (BERTopic + temporal popularity → strong/weak/noise), weak-signal / Topic Emergence Maps, and Rotolo's emergence-attribute operationalisation are all published, open, and Python-implementable.

4. **Other IP offices have already done computational tech-emergence detection** — WIPO Technology Trends (patents + keyword/CPC-IPC classification), EPO's Deep Tech Finder and BERT-based CPC categoriser, and IP Australia's own Patent Analytics Hub feeding the DISR Critical Technologies Hub — giving you direct precedent and reusable methodology, some of it in-house.

5. **Value-pool estimation is the weakest link to automate.** McKinsey-style value pools are gross-margin-by-segment models built from expert assumptions; there is no free API for them. Use proxy signals (patent/publication growth, funding-mention counts, policy salience) as an opportunity-size *index* rather than pretending to size a dollar market.

## Details

### 1. Methodologies to combine

**Strategic-foresight frameworks (classic):**

- **Three Horizons (Bill Sharpe; roots at IIASA; Curry & Hodgson 2008, "Seeing in Multiple Horizons").** Time-phases opportunities: H1 (0–3 yrs, sustain current system), H2 (transition/emerging innovations), H3 (10–30 yr paradigm shifts). Computationally operationalisable: you can *assign* detected trends to horizons using their maturity/growth-curve stage (burst recency + growth rate). The MedTech "MIST" framework (Garcia Gonzalez-Moral & Mkwashi, 2025, DOI 10.1017/S0266462325101153) explicitly overlays Three Horizons onto technology-readiness levels and maps weak-signal sources to each horizon — a direct template for you.
- **STEEPV/PESTLE horizon scanning.** Provides the scan taxonomy (Political, Economic, Social, Technological, Legal, Environmental + Values). UK GO-Science defines horizon scanning as monitoring PESTLE domains to identify "weak signals — emerging issues that could grow in significance." Operationalise as source-tagging and topic-to-category classification.
- **Rotolo, Hicks & Martin (2015), "What is an emerging technology?" (Research Policy 44(10):1827–1843, DOI 10.1016/j.respol.2015.06.006; open preprint arXiv:1503.00673).** Defines five measurable attributes of emergence, verbatim: **"(i) radical novelty, (ii) relatively fast growth, (iii) coherence, (iv) prominent impact, and (v) uncertainty and ambiguity."** This is the single best backbone for a *quantitative* emergence score — each attribute maps to a computable indicator (novelty→embedding distance / first-appearance n-grams; growth→filing/publication CAGR or burst weight; coherence→cluster density; impact→citation/forward-citation counts; uncertainty→dispersion of actors/classifications). The authors themselves note these can be operationalised via "indicators and trend analysis, citation analysis, co-word analysis, overlay mapping, and combinations thereof."
- **Doblin Ten Types of Innovation (Keeley, Pikkel, Quinn & Walters, 2013).** A taxonomy across three clusters — Configuration (profit model, network, structure, process), Offering (product performance, product system), and Experience (service, channel, brand, customer engagement). Use as a *diagnostic checklist* to widen candidate opportunities beyond "new product" — Doblin's research found breakthroughs typically combine multiple types and that product-only innovation gives the lowest ROI. Not computational, but a valuable synthesis-stage lens for a regulator that can innovate in process/channel/engagement, not just products.
- **Value-pool / value-chain mapping (McKinsey/BCG).** A value pool is the gross margin (in dollars) available in a market segment; McKinsey models these bottom-up by segment with macro-adjusted projections and expert assumptions. There is no free feed; treat as an assumption-driven estimate.
- **2×2 prioritisation matrices.** Strategic-fit × trend-maturity, or strategic-fit × asset-leverage. This is your ranking/output stage — fully computable once you have scores on each axis.

**Public-sector toolkits (process scaffolding, mostly qualitative):**

- **OECD OPSI** — Anticipatory Innovation Governance, the Anticipatory Innovation Starter Kit (Portugal's LabX), the Foresight Training Manual, and "Public Sector Innovation Facets: Anticipatory." These frame the four facets and confirm your sprint sits squarely in anticipatory innovation. OPSI's Case Study Library (1000+ cases via the annual "Call for Government Innovations") is a searchable evidence base.
- **UK GO-Science Futures Toolkit (updated August 2024)** — downloadable facilitator worksheets for Horizon Scanning, Three Horizons, Driver Mapping, Scenarios, SWOT, Visioning, Seven Questions, plus Delphi, backcasting and roadmapping. The best single public-sector reference; adapt the *structure* even though delivery is workshop-based.
- **Australian Public Sector Innovation Toolkit** — includes a horizon-scanning practical guide (mirrored on OPSI).

**Which are computationally operationalisable:** horizon scanning (signal collection + NLP classification), weak-signal detection, Three Horizons (via maturity scoring), driver mapping (via co-occurrence networks), technology S-curves/maturity, patent white-space, and 2×2 scoring are all automatable. Scenario planning, visioning, Delphi, and backcasting are inherently participatory and should remain human/qualitative — run them as a lightweight synthesis workshop *after* the pipeline surfaces candidates.

### 2. Data-science / NLP techniques (extending your BERTopic + YAKE + sentence-transformer stack)

- **Kleinberg burst detection.** Kleinberg, J. (2003), "Bursty and Hierarchical Structure in Streams," *Data Mining and Knowledge Discovery* 7:373–397 (DOI 10.1023/A:1024940629314). The premise: "the appearance of a topic in a document stream is signaled by a 'burst of activity,' with certain features rising sharply in frequency as the topic emerges." A two-state (base/burst) automaton flags terms/topics that are uncharacteristically frequent over a limited period; it is the canonical scientometrics method (embedded in CiteSpace, Sci2). A Python implementation exists (nmarinsek/burst_detection). Run it on time-sliced keyword/topic frequencies from your existing YAKE/BERTopic output to flag emerging vs fading themes. Typical parameters in the literature: gamma 1.0, density scaling s=2.0; keep only terms appearing in ≥20 documents to avoid spurious bursts. Note Kleinberg runs on every word (including stop-words) unless pre-processed.
- **BERTrend (Boutaleb et al., 2024, ACL FuturED workshop).** Directly extends BERTopic: processes data in time-sliced batches, merges topics across batches by similarity, tracks a dynamic popularity metric, and classifies each topic as **strong / weak / noise** signal. This is the most natural upgrade to your stack — it reuses your embeddings and BERTopic models and adds the temporal signal-classification layer you're missing. Includes a zero-shot mode for monitoring pre-defined (expert-specified) topics.
- **Weak-signal analysis / Topic Emergence Maps (Ansoff's weak-signal concept; Park & Kim; WISDOM framework, arXiv:2409.15340).** Plot topics on a 2×2 of average topic proportion (x) vs growth rate (y): top-left = weak signals (low volume, high growth), top-right = strong signals. Computable directly from BERTopic topic-proportion time series.
- **Embedding-based novelty/anomaly detection.** Monitor geometric properties of your sentence-transformer embedding space over time to detect the emergence of new topics (arXiv:2111.03496); use distance-to-existing-clusters as a novelty score (maps to Rotolo's "radical novelty"). The "first-appearance n-gram" approach (Arts et al.) treats a word/word-combination appearing for the first time as an emergence marker.
- **Patinformatics / patent white-space.** Segment a technology domain by CPC/IPC classification, build co-occurrence matrices/heatmaps, and identify low-density cells (few patents) as white space = opportunity. The **WIPO Manual on Open Source Patent Analytics** (Paul Oldham, 2nd ed., free, R-based, on GitHub) is the definitive free how-to and explicitly credits IP Australia's IP Analytics Hub in its acknowledgements — a natural reference for you. The companion **WIPO Patent Analytics Handbook** documents spaCy/BERT NLP workflows.
- **Citation-network & co-word analysis.** Co-word/co-occurrence networks for driver mapping; forward-citation counts as an impact/maturity proxy.
- **Technology S-curves / growth-curve estimation.** Fit logistic/Gompertz curves to cumulative patent or publication filings to estimate technology maturity and place a trend on a Three Horizons band (hype-cycle-style maturity mapping is the qualitative analogue).
- **Translating trends → opportunity size.** No free method produces dollar value pools. Build a composite **opportunity-size index** from normalised proxies: filing/publication growth (CAGR + burst weight), funding/venture mentions, news attention (GDELT volume + tone), and policy salience (mentions in strategy/budget docs). Present as a relative index with explicit assumptions, not a market size.

### 3. Data sources mapped to the four inputs

**Strategy (IP Australia + government policy signal):**
- **IP Australia strategy docs** — supplied as fixed context (2026–27 Corporate Plan, 2025 Annual Report). Encode objectives as a reference embedding set to score trend-to-strategy fit.
- **DISR List of Critical Technologies in the National Interest** — seven fields (advanced manufacturing/materials; AI; advanced ICT; quantum; autonomous systems/robotics/PNT/sensing; biotech; clean-energy generation and storage). Free and structured; note IP Australia's own patent data already feeds the associated "Tech Cards." Use as a strategic-priority filter.
- **data.gov.au** — portfolio budget statements, agency reports, Productivity Commission outputs. Free bulk/CSV/API.
- **Parliamentary inquiries / Hansard, Productivity Commission** — policy-salience signals; scrape-friendly and a natural extension of your existing ~150-source monitoring.

**Assets (IP Australia's own data):**
- **IP RAPID** — the weekly-updated successor to IPGOD; patents/trade marks/designs/PBR application + registration data, applicant names/origin, IP right type, classifications. Free on data.gov.au. Your primary asset-leverage dataset.
- **IPGOD / IPLoRD** — 100+ years of registry data across up to ~40 tables; IPLoRD gives an applicant-activity-centric longitudinal view. Millions of rows — use SQLite/DuckDB, not Excel. IP Australia also offers a browser-based IP Data Platform for large-dataset work.
- **TM Checker usage data, AI patent analytics reports, examiner AI use-case trials** — internal assets to match capabilities against opportunities.

**Trends (research + patents + technology):**
- **OpenAlex API** — free, no key required (add `mailto` for the polite pool; a free API key gives ~$1/day of credits, enough for most workflows). As of the OpenAlex Q1 2026 Town Hall roadmap, it indexes **477 million works** ("the largest connected repository of scholarship ever published" — 271.3M core works plus a ~192M-record DataCite/repository set). Bulk monthly snapshot available. Best free research-trend source — ideal for growth-curve and burst analysis on publications.
- **Lens.org** — free for individuals/public-good institutions; Patent + Scholarly APIs (the trial/academic tier is non-commercial and rate-limited; automated/bulk use needs a paid plan, roughly US$1,000–5,000/yr). The free web tool allows downloads of up to 50,000 records at a time. Note: on 1 June 2026 Cambia announced the sale of The Lens to a newly established Australian non-profit, The Lens Limited — re-check free-tier terms before you depend on it.
- **USPTO PatentsView (PatentSearch API + bulk)** — free, disambiguated US patent data, quarterly updates, Python/R wrappers (rOpenSci `patentsview`; WIPO's `patentsviewdata` R package). Full bulk download ~128GB zipped — use the API for targeted pulls.
- **Google Patents Public Datasets on BigQuery** (`patents-public-data`) — SQL access to worldwide bibliographic data. Google Cloud's blog describes the core table as "worldwide bibliographic information on more than 90 million patent publications from 17 countries" plus US full text, sourced from IFI CLAIMS (some current third-party tooling cites 166M+ publications across 100+ countries). First **1 TB/month is free** (BigQuery sandbox needs no credit card); $5/TB thereafter. Best for large-scale CPC-trend and white-space queries — pre-filter by CPC and date to stay under the free cap.
- **EPO OPS / Espacenet, WIPO PATENTSCOPE** — free but lower rate limits; OPS has a Python client (`python-epo-ops-client`).
- **Semantic Scholar API, arXiv, Crossref** — free research/preprint feeds; arXiv is the fastest emergence signal for AI/CS; Crossref for DOI-level metadata. Request an API key / use the polite pool to lift rate limits.
- **GitHub trending/repo activity, Stack Overflow developer trends** — developer-adoption signals via open APIs.

**Value pools / market signals:**
- **GDELT** — free, no key. Per gdeltproject.org, it "monitors print, broadcast, and web news media in over 100 languages from across every country in the world … Its historical archives stretch back to January 1, 1979 and update every 15 minutes." Queryable via the DOC API or BigQuery (bulk is 2.5TB+/yr). Best free proxy for attention/salience and tone; chunk queries longer than 30 days.
- **Google Trends (pytrends, unofficial)** — search-interest proxy; rate-limited and fragile, use sparingly with caching.
- **Crunchbase (limited free/API), OECD innovation statistics, EPO–EUIPO IPR-intensive-industries studies** — venture-funding and economic-contribution proxies.
- **Paid-but-worth-flagging (out of budget):** CB Insights, PitchBook, Gartner (Hype Cycle), Crunchbase Pro — flagged for completeness; the free proxy stack above covers the large majority of the usable signal for a solo, zero-budget build.

### 4. Case studies / precedent

- **WIPO Technology Trends (2019– ).** WIPO's flagship series analyses patent data (PATENTSCOPE/PATSTAT) plus scientific literature; the inaugural AI edition combined keyword/text search of patent texts with CPC/IPC classification codes, expert-validated, capturing AI techniques × functional applications × application fields. It identified "nearly 340,000 AI-related inventions and … over 1.6 million scientific publications … since AI first emerged in the 1950s," with over half of the inventions published since 2013, and WIPO describes it as "the first in a new series from WIPO tracking the development of technologies through the analysis of data on innovation activities." The methodology PDF is public — a direct blueprint for a patents-plus-NLP emergence pipeline.
- **EPO Deep Tech Finder & CPC categoriser (2023– ).** EPO blends patent-register data with startup/business data (Dealroom) to surface startups/universities filing in deep-tech fields, and uses a BERT/transformer model to auto-assign CPC codes from claim text. EPO's Head of Data Science, Alexander Klenner-Bajaja, described training "a BERT model to fill-in-the-blanks on English claim language … then … a CPC symbol to the claim language." Per the EPO (11 June 2025), the tool "has already been used to perform nearly 50,000 searches," covering "over 10,000 startups with European patent applications or granted patents" and "over 1,000 universities." Strong precedent for transformer-based patent NLP inside an IP office.
- **IP Australia Patent Analytics Hub / Office of the Chief Economist.** Your own agency already runs patent analytics (its Patent Analytics Hub cites access to more than 150 million patent records across 250,000 technology classifications) feeding the DISR Critical Technologies Hub. The 2025 Australian IP Report (Ch. 7) states the Data and Analytics team "continued to support the DISR Critical Technologies Hub … to ensure that Australia's critical technology policies are balanced, effective and evidence-based," including patent analytics on quantum. An earlier concrete output (2019) was an interactive visualisation on "Emerging Technologies in Complex Disease Diagnosis." This is internal precedent — and a likely data/collaboration partner.
- **Academic patent+NLP pipelines (Korea/KIPO-adjacent).** LDA/BERTopic + k-means clustering + SAO network analysis + time-series to detect *both* emerging and vacant (white-space) technologies — e.g. the wireless-power-transfer study in *Sustainability* (MDPI, 2019), which "identif[ies] emerging and vacant technology areas … by applying a time series analysis and innovation cycle of technology to the clustering result." Reusable method templates.
- **OECD OPSI Case Study Library.** 1000+ searchable government-innovation cases — use it to find comparable lab processes and to eventually submit your own.

## Recommendations

**Stage the build as a data pipeline — each stage is a reusable module you can point at future ventures.**

**Stage 0 — Strategy encoding (½ day, once; refresh yearly).** Turn IP Australia's strategic objectives, significant initiatives, and the DISR Critical Technologies list into a set of reference embeddings (sentence-transformers) and keyword lexicons. This is your fixed "strategic-fit" target vector.

**Stage 1 — Signal collection (reuse your existing scrapers).** Pull time-stamped documents into SQLite/DuckDB from: OpenAlex (publications), PatentsView + Google Patents BigQuery + Lens (patents, filtered to relevant CPC/IPC and Australia-relevant applicants), IP RAPID/IPGOD (your assets and domestic IP trends), data.gov.au + DISR + Hansard (policy), GDELT + Google Trends (attention). Tag every document with a STEEPV category and its source. Run on GitHub Actions cron.

**Stage 2 — Trend & emergence detection (the core extension).** On the corpus: (a) run BERTopic (existing) → (b) add BERTrend temporal batching to classify topics strong/weak/noise → (c) run Kleinberg burst detection on topic/keyword frequencies → (d) compute a **Rotolo emergence score** per topic from five computable indicators — novelty (embedding distance / first-appearance n-grams), growth (filing/publication CAGR + burst weight), coherence (cluster density/silhouette), impact (citations/forward-citations), uncertainty (dispersion of actors/classifications). Fit logistic S-curves to place each topic on a Three Horizons band.

**Stage 3 — Strategic-fit & asset-leverage scoring.** Score each candidate topic on: strategic-fit (cosine similarity of topic embedding to the Stage-0 strategy vectors + Critical-Tech overlap), and asset-leverage (does IP RAPID/patent data, TM Checker, existing IPAVentures tooling, or examiner AI give you a right-to-play? — computable as overlap between topic classifications and your asset inventory). Add a white-space flag from patent CPC-density analysis.

**Stage 4 — Value-pool / opportunity-size index.** Build a normalised composite index (not a dollar figure): publication+patent growth, GDELT attention/tone, funding-mention proxy, policy salience. Document assumptions explicitly and flag as indicative.

**Stage 5 — Opportunity synthesis & ranking.** Plot candidates on a 2×2 (strategic-fit × emergence/maturity, and a second view strategic-fit × asset-leverage). Overlay Doblin Ten Types as a diagnostic to widen framing. Output a ranked shortlist with per-topic evidence cards (top documents, scores, horizon). *Then* run one short human sense-making session (Seven Questions / lightweight scenario stress-test) on the top ~10 — this is where qualitative foresight adds most value.

**Sequencing for a one-week sprint:** Day 1 — Stage 0–1 (reuse scrapers, add patent/OpenAlex pulls); Days 2–3 — Stage 2 (BERTrend + Kleinberg + emergence score); Day 4 — Stage 3–4 (scoring + index); Day 5 — Stage 5 (ranking, cards, synthesis). Persist all intermediate tables so the pipeline is repeatable and auditable.

**Benchmarks/thresholds that should change your approach:**
- If BigQuery queries approach the 1 TB/month free cap → pre-filter by CPC and date in-query, or shift to PatentsView bulk + local DuckDB.
- If Lens automated pulls are blocked by the (post-June-2026) free-tier terms → fall back to PatentsView + Google Patents BigQuery + EPO OPS for programmatic patent data.
- If BERTrend/emergence scores are noisy on small corpora → raise the minimum-document threshold (the burst literature uses ≥20 docs per term) and lengthen time slices.
- If the value-pool index proves unreliable → drop the dollar pretence entirely and rank on emergence × strategic-fit × asset-leverage only.

**Start-here quick wins:** (1) Add Kleinberg burst detection to your existing YAKE/BERTopic output this sprint — smallest lift, immediate emerging/fading signal. (2) Stand up an OpenAlex + PatentsView puller (both free, low friction). (3) Read the WIPO Manual on Open Source Patent Analytics and the BERTrend paper before building; talk to IP Australia's own Patent Analytics Hub / OCE, who already run patent-based emergence work for the Critical Technologies Hub.

## Caveats

- **The four-input method is a synthesis, not an off-the-shelf product.** You are assembling published components (Three Horizons, Rotolo emergence, BERTrend, patent white-space, 2×2 scoring), so validate weightings against a *known past opportunity* before trusting rankings.
- **Value pools cannot be sized for free.** McKinsey/BCG value pools are proprietary, assumption-heavy gross-margin models. Anything you compute from free proxies is a *relative index*, not a market size — label it as such to avoid over-claiming to stakeholders.
- **Public-sector foresight toolkits are qualitative by design.** OPSI/GO-Science give process legitimacy but almost no computation; don't expect a ready pipeline from them.
- **Emergence detection is sensitive to corpus size, thresholds, and preprocessing.** Kleinberg runs on every word (including stop-words) unless pre-processed, and small corpora produce spurious bursts — keep a human in the loop at synthesis.
- **Patent/publication data lags reality.** Publication delays of ~18 months make patents a lagging indicator of fast-moving software/AI trends — supplement with arXiv, GitHub, and GDELT for faster signals.
- **The Lens ownership/terms changed on 1 June 2026** (new Australian non-profit); its API "free" tier is trial/academic and rate-limited, and bulk/automated use is paid. Re-verify before relying on it.
- **Some sources are explicitly speculative/projected** (e.g. McKinsey energy value-pool figures are modelled forecasts, not facts; some vendor "white-space" and AI-patent-analytics claims are marketing). Treat projected figures as scenarios, not established data.
